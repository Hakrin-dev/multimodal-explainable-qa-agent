## 3. 多模态数据融合处理链路（图 2 素材）

```
                ┌────────── 非结构化侧（B） ──────────┐
PDF ─质量#9─▶复杂度#8─▶解析路由─▶层级切片(面包屑)─▶公式登记#6─▶pgvector+BM25 混合索引
                └──────────────┬────────────────────┘
用户问题 ─▶ 指代消解改写 ─▶ 意图路由 ─▶ ┬ DB_QUERY ─▶ NL2SQL 引擎（A）
                            （A）      ├ DOC_QUERY ─▶ RAG 引擎（B）
                                       ├ HYBRID ─▶ 任务 DAG：DB/文档 子任务（并行/依赖）
                                       │              └─ {tN.result} 紧凑实体回填 ─▶ 融合生成（分区溯源）
                                       └ 公式拦截 ─▶ 公式引擎（文档公式 × DB 参数三通道）
                        └────────── 结构化侧（A）：Chinook 11 表 / pgvector 元数据 ──────────┘
```

**融合链路要点段落**：*“多模态融合不是‘检索后拼接’，而是**规划级融合**：
HYBRID 问题先被分解为带依赖的任务图，数据库子任务与文档子任务按拓扑波次并发执行；
上游结果以紧凑实体（如冠军姓名）注入下游检索词，避免长摘要稀释检索质量；
最终由融合生成器输出带分区溯源（[数据库]/[文档名+页码]）的答案，任何子任务失败均
如实降级而非编造。”*

## 4. 核心创新点摘要（每项含“机制 + 量化证据”）

1. **检索式要素中台（知识外置）**：别名（129 词条/717 别名，含 LLM 生成+规则过滤+人工
   审核闭环）、Schema 业务注释、槽位矩阵、公式资产全部沉淀为**数据库/配置**；
   Prompt 仅含通用能力 → 新领域零改码；配套“品类词黑名单/歧义基础词归并”等治理规则，
   使**别名扩张不损伤精度**（曾凭此发现并修复“歌单名→Music”类灾难改写）。
2. **真依赖任务 DAG 的跨源编排**：规划器输出 `{id, tool, depends_on}` 任务图，拓扑波次
   并行（≤3）+ 占位符依赖注入 + 环容错；实测并行双源端到端 4.6s，五类跨源 11/11。
3. **校验优先的双引擎安全网**：SQL 侧 sqlglot AST + **Schema Linking 选择集白名单** +
   只读执行 + 空结果归因；答案侧逐句引用支撑自检（≤2 轮收敛重写）——“错误在展示前拦截”。
4. **可解释性与成本同源**：同一套 Trace 事件既驱动前端时间线/DAG 与回放，又汇总
   tokens/前缀缓存命中/费用；单轮响应携带成本，账本实测 ¥4.19 完成全流程研发评测
   （≈预算的 0.4%），为“成本工程”提供可举证叙事。
