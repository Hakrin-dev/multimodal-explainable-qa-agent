## 二、验收发现与修复（6 项）

### F1（严重·已修）别名库品类词灾难
LLM 生成的别名把**品类词**绑到具体实体：`Music ← 歌单名/歌单名称/音乐名/曲目名`。
后果：`歌单名字里带 Music 的有哪些？` 被改写成 `Music字里带 Music 的有哪些？`——
语义破坏导致模型查错表（robust-023 根因）。修复：清库 + `gen_aliases.py` 加入
品类词禁令（prompt 约束 4 + `_CATEGORY_WORD` 模式 + blacklist），再生成安全。

### F2（严重·已修）改写器模糊阶段死代码
`rewrite()` 中 `terms` 参数被提前重赋值，`if terms is None:` 永不为真 →
**编辑距离 + pgvector 模糊匹配在生产路径从未运行**（`Muzic→Music` 等错别字纠正失效）。
修复：`db_mode` 先捕获后重赋值；实测 `Muzic→Music`（edit, score 0.5）恢复工作。

### F3（严重·已修）压缩 schema 越界静默执行
Schema Linking 压缩 prompt 后，校验器仍用**全量** schema → 模型可引用未在上下文中的表，
校验通过、执行成功、答案错误（robust-023 第二因：上下文只有 playlist，SQL 却查 track）。
修复：`SQLValidator(allowed_tables=...)` 白名单 + 修复循环反馈可用表清单。

### F4（高·已修）澄清槽位名不稳定致 0/30
澄清评测 30 例全失败：LLM 自由命名（时间范围/对比基准/统计粒度/年份基准…10 种变体）
vs 用例规范名（对比时间范围）。修复三层：① 矩阵拥有**同义词词表**（`synonyms`）+
内核规范化（LLM 标签→规范名，去重保序）；② `SlotMatrix.equivalents()` 词族，
评测端改为**语义等价匹配**；③ 矩阵模式扩面（增长/下降/趋势/差异等表述全覆盖）。
结果：**0/30 → 30/30**（016 词表补全后单例复验通过）。

### F5（中·已修）意图过度澄清 + 改写要素采集
追加 `agent.intent` 规则 5（统计对象/口径已明确时不澄清）与 `agent.rewrite` 规则 4
（多同类要素取**最近轮次**）；PROMPT_TEMPLATE_VERSION → v0.5-w4-accept，契约变更已登记。
